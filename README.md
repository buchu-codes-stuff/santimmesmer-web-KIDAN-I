# ሳንቲም መስመር (Santim Mesmer)

> ገንዘብ መላክ ፣ ማስቀመጥ እና መቀበል ቀላል ነው።
> *Sending, saving and receiving money is easy.*

A phone-number based money app: log in with a PIN, pay a person or a product, and keep track of it all in your receipts.

## Features

- **Login** — phone number (`+251`) and PIN.
- **Dashboard** — landing page after login.
- **Send Money**
  - **Pay a person** — enter their phone number and an amount; looks them up, blocks paying yourself.
  - **Pay a product** — scan the product's QR code with the camera (no manual ID entry); blocks buying your own product.
  - Every payment is confirmed with your PIN before anything moves.
- **Products**
  - Browse products with photo, name and price.
  - **+ button** — add a new product (name, price, optional photo); creates it in the database and shows its QR code right away.
  - Each product's QR code encodes its database ID, which Send Money scans to look it up.
- **Receipts** — history of what you've bought or paid for.
- **Profile** — account section (placeholder).

## Tech stack

- **Frontend:** vanilla JavaScript, HTML, [Bootstrap 5.3](https://getbootstrap.com/) (via CDN)
- **Fonts:** [Inter](https://fonts.google.com/specimen/Inter) (Google Fonts)
- **Backend:** [Supabase](https://supabase.com/) (PostgREST API) — no server code, the frontend talks to Supabase directly
- **QR scanning:** the browser's built-in `BarcodeDetector` where available, falling back to [jsQR](https://github.com/cozmo/jsQR) (loaded from CDN only when needed)

## File structure

```
index.html     Login page / app shell
style.css      All styles (sidebar, cards, hero, animations)
script.js      All app logic (pages, payments, Supabase calls)
```

The app is a single-page app: `script.js` swaps the contents of `#content` (and `#cbody` before login) to switch between pages — there's no routing or page reload.

## Supabase tables used

| Table | Purpose |
|---|---|
| `fayda-identy-test` | User accounts — `id`, `phone`, `first_name`, `last_name`, `ammount` (balance) |
| `products` | Products — `id`, `prod_name`, `prod_price`, `prod_img`, `prod_by` (seller's user id) |
| `recipts` | Receipts — `buy_by`, `prod_name`, `price` |

> Table/column names (`ammount`, `recipts`) are kept as-is to match the existing database — fix the typos there too if you ever rename the columns.

## Running it

1. Serve the three files with any static web server (QR camera scanning needs **HTTPS** or `localhost` — it won't work opened directly as a `file://` path).
2. Make sure your Supabase project has:
   - Row-level security policies that allow the app to `select`, `insert`, and `update` the tables above with the key used in `script.js`.
   - The `products.id` column auto-generated by the database (e.g. a `uuid` default), since new products don't set an ID themselves.
3. Open `index.html` and log in with a phone number that exists in `fayda-identy-test`.

## Known gaps / next steps

- Money transfers update the two balances with two separate requests, not inside one database transaction. If you want this to be fully safe for real money, move it into a Postgres function (RPC) so both updates happen atomically.
- The Profile page isn't built yet.
- No sign-up flow — accounts are assumed to already exist in the database.
